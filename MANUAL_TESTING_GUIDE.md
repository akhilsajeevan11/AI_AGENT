# Manual Testing Guide for CrewAI Hospital Administration Agent

This guide provides steps for manually testing the CrewAI-based Hospital Administration Agent (`main_crew.py`).

## Prerequisites

1.  **Environment:**
    *   Python 3.x installed.
    *   Required Python packages installed. From the project root, run:
        ```bash
        pip install -r requirements.txt 
        ```
        (Assuming a `requirements.txt` file is created listing `crewai`, `langchain`, etc. If not, use the command from README: `pip install crewai crewai[tools] langchain langchain-community langchain-openai python-dotenv langchain-groq`)
2.  **API Keys:**
    *   The application now uses LLMs via CrewAI, which requires API keys for the chosen LLM provider (e.g., OpenAI, Groq).
    *   Copy the `.env.example` file to a new file named `.env` in the project root:
        ```bash
        cp .env.example .env
        ```
    *   Edit the `.env` file to include your actual API key(s) for the LLM provider you intend to use (e.g., `OPENAI_API_KEY="sk-..."`).
    *   You can also set `LLM_PROVIDER` (e.g., `LLM_PROVIDER="groq"`) and specific model names (e.g., `GROQ_MODEL_NAME="mixtral-8x7b-32768"`) in the `.env` file. If not set, it defaults to OpenAI.
3.  **Files:** Ensure all project files are present:
    *   `main_crew.py` (the new main application script)
    *   `crew_definitions.py`
    *   `database_tools.py`
    *   `database_manager.py`
    *   `hospital_schema.sql`
    *   `.env` (after creating it from `.env.example` and adding your keys)
4.  **Initial Database State (Recommended):**
    *   To start with a clean, predictable database for testing, run the `database_manager.py` script directly once before starting your test session:
        ```bash
        python database_manager.py
        ```
    *   This creates/overwrites `hospital_management.db` with initial test data (e.g., Dr. Alice Brown - Cardiology, Dr. Bob Green - Neurology; some availability for Dr. Brown on 2024-08-20).
5.  **SQLite Browser (Optional but Recommended):**
    *   A tool like DB Browser for SQLite is helpful for inspecting `hospital_management.db`.

## Running the Agent

1.  Open your terminal or command prompt.
2.  Navigate to the project directory.
3.  Run the agent:
    ```bash
    python main_crew.py
    ```
4.  The application will attempt to initialize the LLM (displaying provider and model info or errors if keys are missing/invalid) and then show the main menu.

## Test Scenarios

**Important Note on Expected Output:** Since the agent's responses are generated by an LLM, the exact wording may vary. Focus on whether the core information is present and the requested action is confirmed or correctly reported as failed. Check the database for definitive proof of data changes.

### Scenario 1: New Patient Registration

1.  **Action:** At the main menu, select option `1` ("Register New Patient").
2.  **Input:** Provide details when prompted by `main_crew.py`:
    *   First name: `CrewTest`
    *   Last name: `PatientOne`
    *   Date of birth (YYYY-MM-DD): `1992-02-02`
    *   Gender: `Male`
    *   Phone number: `5552220001` (unique)
    *   Email: `crew.patient1@example.com` (unique)
    *   Address: `202 Crew Street, AItown`
3.  **Expected Output (from CrewAI agent):**
    *   A message confirming successful registration, ideally including the new Patient ID. Example: "Patient CrewTest PatientOne has been successfully registered with ID: <new_patient_id>." or similar.
4.  **Database Verification:**
    *   `SELECT * FROM Patients WHERE phone_number = '5552220001';` (Verify all details).
    *   `SELECT * FROM ConversationLogs WHERE intent_detected = 'audit_patient_registered';` (Check for a relevant log entry).

### Scenario 2: View Patient Appointments

*(Assumes patient "Jane Smith" with phone `0987654321` exists from `database_manager.py` initial data, and may have appointments).*

1.  **Action:** Main menu, select option `2` ("View Patient Appointments").
2.  **Input:**
    *   Patient's phone number: `0987654321`
3.  **Expected Output (from CrewAI agent):**
    *   A list of Jane Smith's appointments (if any), showing details like Appointment ID, Doctor, Date/Time, Status. If no appointments, a message stating that.
    *   Example: "Found patient Jane Smith. Here are their appointments: \n- Appointment ID: 2, Doctor: Dr. Alice Brown, Date: 2024-08-15 11:00:00, Status: Scheduled"
4.  **Database Verification:**
    *   `SELECT * FROM Patients p JOIN Appointments a ON p.patient_id = a.patient_id WHERE p.phone_number = '0987654321';`
    *   Verify the appointments listed match the database records.
    *   Check `ConversationLogs` for `audit_viewed_appointments`.

### Scenario 3: Find Doctor Availability

*(Assumes Dr. Alice Brown (ID 1) exists from initial data).*

1.  **Action:** Main menu, select option `6` ("Find Doctor Availability").
2.  **Input:**
    *   Doctor ID: `1`
    *   Start date (YYYY-MM-DD or YYYY-MM-DD HH:MM:SS): `2024-08-20`
    *   End date (YYYY-MM-DD or YYYY-MM-DD HH:MM:SS): `2024-08-20`
3.  **Expected Output (from CrewAI agent):**
    *   A list of available slots for Dr. Alice Brown on that date. Seed data includes slots like `Availability ID: 1, Start: 2024-08-20 09:00:00, End: 2024-08-20 12:00:00, Booked: Yes` and `Availability ID: 2, Start: 2024-08-20 14:00:00, End: 2024-08-20 17:00:00, Booked: No`. The agent should ideally list only unbooked slots or clearly state the status.
    *   The task definition for `find_doctor_availability_task_def` asks for "available (not booked) time slots".
4.  **Database Verification:**
    *   `SELECT * FROM DoctorAvailability WHERE doctor_id = 1 AND date(start_time) = '2024-08-20';`
    *   Compare with agent output.

### Scenario 4: Schedule New Appointment

*(Requires a known `patient_id`, `doctor_id`, and a *valid, unbooked* `availability_id` from Scenario 3. Let's assume Patient ID 2 (Jane Smith) and Doctor ID 1 (Alice Brown), and Availability Slot ID 2 from the seed data is available).*

1.  **Action:** Main menu, select option `3` ("Schedule New Appointment").
2.  **Input:**
    *   Patient ID: `2`
    *   Doctor ID: `1`
    *   Doctor Availability Slot ID to book: `2` (this is the slot 2024-08-20 14:00:00 - 17:00:00)
    *   Desired appointment date and time (YYYY-MM-DD HH:MM:SS, must match slot start time): `2024-08-20 14:00:00`
    *   Appointment duration in minutes (e.g., 30): `30` (or it could be derived by the agent from the slot duration)
    *   Reason for visit: `Follow-up consultation`
3.  **Expected Output (from CrewAI agent):**
    *   Confirmation: "Appointment scheduled successfully. Appointment ID: <new_appt_id>, Patient ID: 2, Doctor ID: 1, Slot ID: 2, Time: 2024-08-20 14:00:00."
4.  **Database Verification:**
    *   `SELECT * FROM Appointments WHERE availability_id = 2;` (Verify new appointment details, status 'Scheduled').
    *   `SELECT is_booked FROM DoctorAvailability WHERE availability_id = 2;` (Verify `is_booked` is now `1`).
    *   Check `ConversationLogs` for `audit_appointment_scheduled`.

### Scenario 5: Cancel an Appointment

*(Requires an existing 'Scheduled' appointment. Use the one created in Scenario 4, let's say its ID is `<new_appt_id>` and its `availability_id` is `2`)*

1.  **Action:** Main menu, select option `4` ("Cancel Appointment").
2.  **Input:**
    *   Patient ID (optional): `2`
    *   Appointment ID to cancel: `<new_appt_id_from_scenario_4>`
    *   Availability Slot ID (if known): `2`
3.  **Expected Output (from CrewAI agent):**
    *   Confirmation: "Appointment ID <new_appt_id> has been successfully cancelled. Availability slot ID 2 has been made available again."
4.  **Database Verification:**
    *   `SELECT status FROM Appointments WHERE appointment_id = <new_appt_id_from_scenario_4>;` (Verify `status` is 'Cancelled').
    *   `SELECT is_booked FROM DoctorAvailability WHERE availability_id = 2;` (Verify `is_booked` is now `0`).
    *   Check `ConversationLogs` for `audit_appointment_cancelled`.

### Scenario 6: List All Doctors

1.  **Action:** Main menu, select option `7` ("List All Doctors").
2.  **Input:** No further input needed.
3.  **Expected Output (from CrewAI agent):**
    *   A list of all doctors from the database (e.g., Dr. Alice Brown, Dr. Bob Green, Dr. Eve White from seed data) with their details.
4.  **Database Verification:**
    *   `SELECT * FROM Doctors;` (Compare with agent output).

### Scenario 7: List Doctors by Specialization

1.  **Action:** Main menu, select option `8` ("List Doctors by Specialization").
2.  **Input:**
    *   Specialization: `Cardiology`
3.  **Expected Output (from CrewAI agent):**
    *   A list of doctors matching 'Cardiology' (e.g., Dr. Alice Brown, Dr. Eve White).
4.  **Database Verification:**
    *   `SELECT * FROM Doctors WHERE specialization = 'Cardiology';`

### Scenario 8: List All Doctor Specializations

1.  **Action:** Main menu, select option `9` ("List All Doctor Specializations").
2.  **Input:** No further input needed.
3.  **Expected Output (from CrewAI agent):**
    *   A list of unique specializations (e.g., "Cardiology", "Neurology").
4.  **Database Verification:**
    *   `SELECT DISTINCT specialization FROM Doctors;`

### Scenario 9: Reschedule Appointment (Guided Flow)

1.  **Action:** Main menu, select option `5` ("Reschedule Appointment").
2.  **Input:**
    *   The flow will first guide you through cancelling an appointment (follow prompts similar to Scenario 5). Assume you cancel an existing appointment.
    *   Then, it will ask if you want to schedule a new one. Enter `yes`.
    *   The flow will then guide you through scheduling a new appointment (follow prompts similar to Scenario 4).
3.  **Expected Output:**
    *   Confirmation of the cancellation.
    *   Confirmation of the new appointment booking.
4.  **Database Verification:**
    *   Verify the old appointment is 'Cancelled' and its slot (if applicable) is free.
    *   Verify the new appointment is 'Scheduled' and its slot is booked.

## Troubleshooting / Observation

*   **Verbose Output:** The `main_crew.py` script sets `verbose=2` for the Crew and `verbose=True` for Agents. Observe the terminal output to see:
    *   Which agent is working on the task.
    *   Which tools the agent decides to use.
    *   The parameters passed to the tools.
    *   The results from the tools.
    *   The agent's thought process and final answer.
*   **LLM Responses:** If the LLM's response is not what you expect or if it fails to use tools correctly, the task description in `crew_definitions.py` for that specific task might need to be clearer or more directive. Tool descriptions in `database_tools.py` are also critical.
*   **Database State:** Always be aware of the current state of your `hospital_management.db`. If a test fails due to data issues (e.g., trying to book an already booked slot without realizing it), reset the database using `python database_manager.py` and try the scenario again with careful attention to IDs and current data.
*   **API Keys:** Ensure your `.env` file is correctly set up with valid API keys and the correct `LLM_PROVIDER` if not using the default (OpenAI).

This guide should help in manually testing the core functionalities of the CrewAI-based Hospital Administration Agent.
